# 検索と公告取得の分離（2026-09-19 改訂）

- 通常の「検索」・Enter・絞り込み・ページ送りは保存済みデータへの GET のみ。外部サイトへのアクセスや収集キューの読み込みはしない。
- 「最新情報を取得」だけが外部取得を開始する。1回につき調査対象の公告100件または60秒を上限とし、条件一致100件を待たない。取得中も通常検索・閲覧できる。画面を閉じた場合の続行は、次回の明示的な取得操作で行う。
- 保存検索は候補100件の表示枠、1ページ12件。「保存済みからさらに100件表示」は表示枠を増やすだけで外部取得しない。固定資格・等級、会員ごとの確認履歴・Lark保存先を維持する。
- 新規・更新公告は保存時に検索用本文の正規化、機関名の除去、資格・等級判定を行う。SQLで語句の一致位置を求め、並べ替えには本文を含まない情報だけを返す。カード12件の原文は最後に読み込む。
- migration 0009 は列・索引の追加のみ。既存データの準備は認証済み検索の応答後、Worker の waitUntil で40件ずつ、最大10バッチ／20秒。原文・変更日時・指紋・確認履歴を書き換えず、準備中の行は従来判定で検索できる。再取得との競合は原データ一致条件で防ぐ。判定ルール変更時は discoverySearchVersion を更新する。
- サーバー計測は Server-Timing: saved-search、ブラウザーの検索操作からカード描画までは Performance の portal-search-to-cards。検索語や個人情報は計測先に送信しない。
- 定期収集用の scheduled ハンドラーはあるが、定期スケジューラは未接続。今回の変更は定期収集が自動で稼働するという意味ではない。

以下は以前の調査・実装記録（数値や旧操作名は当時のもの）。

# 保存型の案件収集

## 稼働範囲

- `GET/POST /api/discovery` はログインなしのゲストも利用できる。確認履歴・検索条件・自社条件はブラウザ単位、案件と収集結果は共有。管理者操作には管理者認証が必要。
- 全利用者・3タブで1つの収集キューを共有。確認済み・対象外は利用者とタブごと。
- 官公需 API は4語ずつ・1回50件で取得し、4MBを超える応答は同じ条件の10件・1件で再試行する。件数超過時は公告・取得日の区間を分割し、未検索のキーワード群を先に一巡してから分割した範囲を調べる。最初は期間を限定しない。分割は2000年以降、最大22段階、待機500条件まで。未取得範囲は取得状況に残す。
- 防衛省内局の見積募集、陸自20機関、海自3区分、空自28機関から公開ページをたどる。各隊最大300ページ、機関ごと30ページ、深さ5まで。全件網羅を保証しない。
- 先に通常のHTTPでHTML・文字入りPDFを読む。robots.txt、許可した調達URL、各リダイレクトを確認。403/429・確認画面を回避しない。サイト単位の停止と失敗を保存する。
- 取得は共有ロックで直列化。処理間は最低5秒、ページ本文は6時間キャッシュ。再巡回は6時間以上空ける。失敗したAPI条件だけの再試行は5分空け、成功した条件を再取得しない。これは内部の負荷制御値であり、運営者が保証する許可頻度ではない。
- PDFの40ページ制限は撤廃。ページを順番に読み取り、ページごとにリソースを解放する。1ファイル8MB・抽出本文150万文字の上限は維持。途中結果の永続保存は未実装で、1ファイルの読み取り完了後に保存する。画像PDFのOCRは未接続。既知の案件名・URLがあれば「要確認」に保持する。無効・不明な日付を推測しない。
- 調達ポータル・NJSSは準備中。自動アクセス・スクレイピングを行わない。

## 一覧と期限

おすすめ20件は表示上のページサイズ。保存した結果は次ページから確認可能。
同じ原文URLと正規化した件名を重複キーとする。別URLの案件を類似度だけで統合しない。
入札開始・開札・納入期限を入札締切として扱わない。日本時間の当日以前は主一覧から除外。
締切不明・先行手続きの期限到来・確認後の変更は要確認。手動で原文確認した締切は確認者と根拠を付けて保存する。
資格とオープンカウンターは独立の条件で、参加資格の適否を自動判定しない。
一覧は条件に合う保存案件を100件ずつ最大20,000件まで走査し、上限到達時は画面で通知する。
Larkは既存の3テーブルとフィールドを利用し、利用者が押した案件だけ登録する。

## 定期実行の状態

`worker/index.ts` に scheduled ハンドラーを実装したが、Sitesの通常公開だけではCronは登録されない。
現在は定期実行未接続。画面を閉じるとブラウザからの次ステップ呼び出しは止まり、処理位置・候補はD1に残る。
画面や運用報告で「定期収集が稼働」と表示してはいけない。
公開先のスケジューラ接続・権限を確認してから、実際の定期実行経路を構成する必要がある。
利用者のCloudflareアカウントからSites管理下のWorkerを変更できるとは限らない。
外部Workerを使う場合は、収集専用の機械間認証と取り込み経路を別途実装する。ログイン制限を緩めたり、サイト発行のトークンを利用者IDとして偽装してはならない。
実行された scheduled ハンドラーだけが `scheduler-heartbeat` を更新する。1回につき最大8ステップ。
UIはこの実行時刻を表示し、接続前は明確に「接続待ち」と表示する。

## 検証

`tests/discovery.test.mjs` は実SQLをSQLiteで実行し、21組合せの対象タブ・出典の絞り込み、重複、20件超のページング、期限不明保持、更新後の再確認、権限、API分割、並行ロック・アクセス拒否を検証する。

## 2026-09-12 取得0件の障害修正

本番の `discovery_runtime` は21回処理・保存0件、API17回すべてが Workers の `Invalid redirect value` で失敗していた。候補テーブルにも行がなかった。
`redirect: "error"` を利用していた官公需API、robots.txt、Cloudflare Browser REST、Lark RESTを、`manual` と3xxの明示的な拒否に統一。リダイレクト先へ認証情報を転送しない。
この通信設定エラーが記録された保存0件の旧状態だけは、次の開始操作で再構成する。未送信の失敗に6時間待機を適用しない。
その他の取得失敗は正常終了・検索0件とは区別して表示し、失敗したAPI条件を保持する。取得エラーと保存件数を一覧付近に表示し、取得状況を開いて提示する。
現在はユーザーの指定によりログイン不要で利用できる。管理者限定の設定は保護する。

## 2026-09-16 取得信頼性と日次通知の準備

- 陸自20、海自3、空自28の計51区分を確認表に表示。各区分のページ処理数・待機数・未取得・取得上限・最終試行/成功を表示。過去の実行に時刻記録がない場合は推測せず記録なし。
- 再取得に失敗しても、前回の本文・締切・最終取得時刻・変更履歴を上書きしない。「要確認」に戻し、再取得失敗を明示。成功した次の取得で警告を解除する。
- 保存型収集は締切済みの公告も保持する。通常検索では従来どおり未来の締切が対象。過去情報は詳細条件で参照できる。
- 取得失敗をナビゲーターでも明示し、検索0件と案内しない。
- `POST /api/notifications/daily-digest` は専用の `LARK_DIGEST_TOKEN` によるBearer認証。キー未設定503、不一致401。通常のメンバー権限や管理者権限は付与しない。レスポンスは `{date,message}`、読み取りのみ。
- 通知内容は過去24時間の新規保存・内容更新件数、本日から7日後までの保存候補最大5件、ポータル管理中の提出前案件最大5件、取得状況。Lark Base側だけで管理されている情報の集計ではない。公告変更の自動登録や無人収集は行わない。
- Larkの設定案：既存Base【SFL/LUCIA】入札案件管理、毎日08:00（日本時間）、終了なし、HTTP POSTで上記エンドポイント、本文 `{}`、JSONレスポンスの `message` を同名グループへ送信。通知でポータルURLも案内する。
- **未稼働**：専用キーをLark設定へ保存する操作は、自動承認審査が「外部への認証情報保存には個別承認が必要」として拒否した。キーはSites側にのみ設定済み。Lark側は未保存・未有効化。承認後に設定・単発試験・実行ログ/到着確認を行う。既存3つの案件登録通知は変更していない。
- Larkのこの自動化画面の最小繰り返し単位は日。短い間隔での継続収集用スケジューラは未接続。日次レポートを収集の稼働証拠にしてはいけない。
- 検証環境で新規収集は21処理とも通信エラーとなり実取得未確認。本番で全取得先の再検証が完了したとは報告しない。開発プレビューはWorker入口を通らずゲストCookieの継続を検証できないため、ゲスト保存はコンパイル済みWorkerの経路でも検証する。

## 参加資格による表示制限（2026-09-16）

- SFL・エンジニア・Academy共通で、全省庁統一資格の利用を認める記載がある案件、またはオープンカウンターを表示する。一般的な資格案内リンクや国の機関名だけでは判定しない。
- 自治体独自資格・業者名簿登録・建設工事等の別資格が必須と読み取れる場合は除外する。統一資格との選択が同一条項で明記された場合は統一資格対象とする。複雑な例外・条項間の選択は推測しない。
- 自治体のオープンカウンターで統一資格の利用条件がない場合は、独自資格・名簿登録が不要との記載がある場合だけ表示する。履行地域の都道府県名を資格や発注主体と混同しない。
- 保存結果は表示時に再判定し、資格条件が未確認の候補も非表示にする。元の候補・確認履歴は削除しない。絞り込みは件数・ページングより前に適用し、保存検索や「対象案件すべて」でも解除しない。週次通知の期限候補も同じ条件にする。
- 「全省庁統一資格対象」は資格ルートの一致であり、個別企業の等級・営業品目・地域・実績・有効期間を満たす保証ではない。必須と明記された場合のみ「全省庁統一資格必須」と表示する。
- 公式確認先：調達ポータル https://www.p-portal.go.jp/how_to_use 、統一資格説明 https://www.p-portal.go.jp/pps-web-biz/geps-chotatujoho/resources/app/html/shikaku.html 、防衛省のオープンカウンター実施要領 https://www.mod.go.jp/js/pdf/supply/announcement/opencounter.pdf 。
- 過去の承認待ち記録に対する運用更新：週次通知は利用者承認後にLarkへ保存して有効化済み。2026-09-16 12:34（日本時間）の実行ログで取得・送信成功を確認し、毎週月曜10:00、初回9/21へ設定済み。
